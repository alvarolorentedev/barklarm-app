# Phase 2.1 — intelligence hardening validation

Status: implemented and verified on macOS arm64. Other targets are compiled/packaged but not runtime-qualified.

## Scope

This report records the Phase 2.1 hardening validation. It is not a new model-selection exercise. The default remains
Qwen3-1.7B-Instruct Q4_K_M, pinned by `src-tauri/src/intelligence/model-manifest.json`.

- Prompt: `diagnostic-analysis-v1` (unchanged).
- Runtime: llama.cpp `b12732`, macOS arm64 CPU build.
- Effective context: 8192 tokens; output budget: 1536 tokens; temperature 0.2.
- Fixture revision: `1b607d6ecdf8cbb941b61174871bbc23c1a8df19bd318b41ff8349cca4d4575e` (18 fixtures, 3 held out).
- Harness: production `AnalysisManager` -> context assembler -> prompt -> provider -> validator -> repair.

## Evaluation limitations

- The fixture set is synthetic, small and single-language.
- Held-out cases were not used for tuning during this phase. If future prompt/rule changes use them, they must be
  relabelled and a replacement held-out set created.
- The harness separates model safety from application guards, but a structurally valid wrong diagnosis is still scored
  by the human rubric, not by literal substring checks.
- One platform and one runtime artifact were measured. CPU frequency, thermal state and model cache affect latency.

## Native runtime smoke

`bun run sidecar:smoke:runtime` verified:

1. The pinned model file exists, matches its manifest size and SHA-256.
2. The staged llama.cpp binary and libraries are present.
3. The runtime starts with Barklarm's argument allowlist and becomes ready.
4. The listener is loopback-only.
5. Unauthenticated model listing and inference are rejected.
6. A structured `json_schema` inference request returns a response that passes the production validator.
7. Shutdown removes the owned process and the temporary token file.

This is a direct runtime-boundary test, not a claim that every packaged platform has been interactively qualified.

## Native packaged-app smoke (macOS arm64)

A release bundle was built with `bun run build` and launched with a non-committed config pointing at a real failed
public GitHub Actions run (`actions/runner`, workflow 281296085) using the locally authenticated GitHub CLI token only
for retrieval. The token was not written to the repository or any committed artifact.

Observed:

1. The app launched and bundled `llama-server` plus only shared libraries/licenses.
2. It started exactly one owned `llama-server` child with the loopback argument allowlist.
3. `lsof` showed the listener on `127.0.0.1:<port>` only.
4. The token file was absent after startup; the ownership marker contained PID/start identity/executable/owner.
5. `nettop` recorded real bytes in both directions between the app and the managed runtime, proving the Tauri HTTP
   transport reached the CSP-blocked loopback port and an inference request/response completed.
6. A graceful AppleEvent quit removed the app, the owned child, the marker and all token files. An earlier SIGTERM
   (abrupt) left the child until the next launch cleaned it by identity, which is the documented abrupt-termination
   limitation.

Not interactively verified: viewing the rendered citation panel in the webview and disabling intelligence through the UI.
The window is hidden by design and this environment has no usable screen/UI automation. The same stop path is exercised
by graceful quit, `stop_managed_runtime` unit/state tests and the runtime smoke. This remains a manual UI validation item.
